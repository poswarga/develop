Pakai backup aman saja cukup ganti nama tables


Baik, saya buatkan query SQL lengkap untuk backup dan restore per tabel. Karena Anda menggunakan akun gratis Supabase, kita akan dump struktur + data menggunakan query SELECT dan generate ulang saat restore.

---

📦 QUERY BACKUP (Jalankan di Supabase SQL Editor)

1. Backup Tabel profiles

```sql
-- ============================================================
-- BACKUP: profiles
-- ============================================================

-- 1A. Lihat struktur tabel
SELECT 
  column_name,
  data_type,
  is_nullable,
  column_default
FROM information_schema.columns
WHERE table_schema = 'public' 
  AND table_name = 'profiles'
ORDER BY ordinal_position;

-- 1B. Export semua data sebagai JSON (copy hasilnya)
SELECT jsonb_agg(row_to_json(t)) AS backup_data
FROM (
  SELECT * FROM profiles ORDER BY created_at DESC
) t;

-- 1C. Atau export sebagai CSV readable (copy hasilnya)
SELECT 
  id,
  full_name,
  email,
  phone,
  role,
  avatar_url,
  bio,
  badge,
  jabatan,
  barcode_url,
  is_admin,
  is_active,
  address,
  alias,
  created_at,
  updated_at,
  upgraded_at
FROM profiles
ORDER BY created_at DESC;
```

🔄 QUERY RESTORE (Jalankan di Supabase SQL Editor)

Cara Restore Data

PENTING: Backup dulu data yang ada sebelum restore! Jangan restore ke database production langsung tanpa backup.

Restore Tabel profiles

```sql
-- ============================================================
-- RESTORE: profiles
-- Hapus data lama, lalu insert data backup
-- ============================================================

BEGIN;

-- Hapus data lama (hati-hati!)
DELETE FROM profiles;

-- Insert data backup (ganti [...] dengan data JSON dari hasil backup)
INSERT INTO profiles (
  id, full_name, email, phone, role, avatar_url, bio, 
  badge, jabatan, barcode_url, is_admin, is_active,
  address, alias, created_at, updated_at, upgraded_at
)
SELECT 
  rec->>'id',
  rec->>'full_name',
  rec->>'email',
  rec->>'phone',
  rec->>'role',
  rec->>'avatar_url',
  rec->>'bio',
  rec->>'badge',
  rec->>'jabatan',
  rec->>'barcode_url',
  (rec->>'is_admin')::boolean,
  (rec->>'is_active')::boolean,
  rec->>'address',
  rec->>'alias',
  (rec->>'created_at')::timestamptz,
  (rec->>'updated_at')::timestamptz,
  (rec->>'upgraded_at')::timestamptz
FROM jsonb_array_elements('[COPY_JSON_BACKUP_DISINI]'::jsonb) AS rec;

COMMIT;
```

📋 Panduan Lengkap Backup & Restore

Cara Backup:

1. Buka Supabase SQL Editor
2. Jalankan query "Export sebagai JSON" untuk setiap tabel (1B, 2B, 3B, 4B, 5B)
3. Copy hasilnya (format JSON array) ke file .txt atau .json
4. Simpan dengan nama: backup_profiles_20260802.json, backup_article_index_20260802.json, dst.

Cara Restore:

1. Buka Supabase SQL Editor
2. Buka file backup Anda
3. Copy isi JSON array
4. Ganti teks [COPY_JSON_BACKUP_DISINI] di query restore dengan JSON backup Anda
5. Jalankan query restore

Contoh Penggunaan:

```sql
-- Contoh: Restore info_board dengan 2 data

BEGIN;
DELETE FROM info_board;
INSERT INTO info_board (id, message, sender_name, sender_role, sender_avatar, is_active, created_at)
SELECT 
  (rec->>'id')::int,
  rec->>'message',
  rec->>'sender_name',
  rec->>'sender_role',
  rec->>'sender_avatar',
  (rec->>'is_active')::boolean,
  (rec->>'created_at')::timestamptz
FROM jsonb_array_elements('[
  {"id":1,"message":"Selamat datang di POS WARGA!","sender_name":"Admin","sender_role":"admin","sender_avatar":null,"is_active":true,"created_at":"2026-01-01T00:00:00+00:00"},
  {"id":2,"message":"Fitur baru telah hadir!","sender_name":"Editor","sender_role":"editor","sender_avatar":null,"is_active":true,"created_at":"2026-06-01T00:00:00+00:00"}
]'::jsonb) AS rec;
COMMIT;
```

⚠️ Peringatan Penting

1. Jangan restore ke production langsung — Tes dulu di environment development
2. ID akan tetap sama — Jika ada data baru dengan ID yang sama, akan conflict. Gunakan DELETE dulu sebelum INSERT
3. RLS tidak terganggu — Restore data tidak memengaruhi Row Level Security
4. Trigger auto-generate — Beberapa kolom seperti created_at mungkin di-override oleh trigger. Sesuaikan jika perlu
5. Simpan backup di tempat aman — Jangan commit ke repository publik (mengandung data user)
